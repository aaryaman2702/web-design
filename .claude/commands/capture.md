# /capture

The command that makes everything else compound. Run it at the end of real work.

Without this, JARVIS accumulates transcripts and calls it memory.

## Procedure

Run the **reflection engine** against what just happened.

1. **The seven questions** — worked, didn't, surprised, permanent, principle,
   change, more capable. Honestly. Performed reflection is worse than none,
   because it fills the graph with noise that later reasoning must wade through.

2. **Climb the generalisation ladder.** Observation → pattern → principle. Stop
   at the highest rung that still constrains a decision. One rung further
   produces platitudes.

3. **Write the episode.** Immutable, timestamped, in `memory/episodes/sessions/`.

4. **Write any insights.** Edged `learned_from` back to the episode. Confidence
   and review date on each.

5. **Route the signals:**
   - Aesthetic judgment or correction → taste engine
   - Surprise or contradiction → curiosity engine
   - Repeated workflow → evolution engine, as a candidate module
   - Outcome of a prior decision → decision engine, for calibration

6. **Update `memory/self/state.md`** if what's live changed.

## Scale to what happened

A one-line fix gets one line, or nothing at all. A three-hour build gets a real
record.

Reflecting on everything equally is the failure mode — it buries genuine insight
under dutiful notes about nothing, and the graph gets harder to use with every
entry.

## The last question

*Is he more capable than before?*

When the answer is no — and sometimes it will be, which is fine — record why.
The pattern across those answers is where this system's next upgrade is hiding.
